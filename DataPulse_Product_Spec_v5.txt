SECURITY

- No public access to uploaded datasets under any circumstance.
- Shared links do not expire automatically (MVP). Manual revoke by owner.

RELIABILITY
-----------
- Report generation success rate       ≥ 99%
- AI Summary generation success rate   ≥ 95%
- Alert generation success rate        ≥ 99%
- PPTX export success rate             ≥ 95%

AI COST MANAGEMENT
------------------
Problem:
  If every dataset load triggers a fresh LLM call, a user who uploads
  10 datasets in one session generates 10 API calls. At scale this
  becomes expensive and slow.

Rule:
  Generate AI Executive Summary ONCE on dataset upload.
  Cache the result against the dataset ID.
  Serve cached summary on all subsequent views.
  Only regenerate when:
    (a) User explicitly clicks "Regenerate Summary", OR
    (b) Dataset is replaced or updated.

Applies to: Executive Summary, AI Comparison Summary, Insight Confidence.
This rule is a performance optimisation AND a cost control.
Both reasons matter.

----------------------------------------------------------------
DATASET QUALITY SCORE FORMULA
----------------------------------------------------------------

Quality Score is a composite metric, always expressed as a percentage.

  Quality Score =
    Completeness Score    × 0.40
  + Duplicate Score       × 0.30
  + Consistency Score     × 0.20
  + Formatting Score      × 0.10

Component Definitions:

  Completeness Score
    = (Total cells - Empty cells) / Total cells × 100
    Empty cell = null, blank string, or "N/A" literal.

  Duplicate Score
    = (Total rows - Duplicate rows) / Total rows × 100
    Duplicate row = all column values identical to another row.

  Consistency Score
    = (Rows passing type checks) / Total rows × 100
    Type check = each column's most common data type applied to all rows.
    Example: If "Budget" column is 95% numeric, non-numeric rows fail.

  Formatting Score
    = (Columns with consistent formats) / Total columns × 100
    Checks: date formats, currency formats, casing consistency.

Weight Justification:
  Completeness (40%) is weighted highest because missing data has the
  greatest impact on analysis accuracy. An insight drawn from incomplete
  data is unreliable regardless of how clean the rest is.
  Duplicates (30%) are second because they directly distort aggregations —
  a duplicated high-value row inflates averages and misleads every
  downstream calculation.
  Consistency (20%) matters but has lower impact because type
  mismatches usually affect a minority of rows, not the whole dataset.
  Formatting (10%) is cosmetic relative to the others — a date formatted
  as DD/MM instead of MM/DD rarely changes a business conclusion.
  These weights may be revised based on user feedback after Sprint 2 ships.

Grade Bands:
  90–100%   Excellent
  75–89%    Good
  60–74%    Fair
  Below 60% Needs Attention

This formula is used identically on:
  - Dataset card in workspace
  - Smart Alerts (data quality alert)
  - Compare page scorecard
  - Report quality section

SMART ALERT THRESHOLD DEFINITIONS
----------------------------------------------------------------

All thresholds are exact. Developers must not interpret or adjust these
without a spec update.

MISSING VALUES ALERT         [Severity: High]
  Trigger: Missing value rate > 5% of total cells
  Formula: (Empty cells / Total cells) × 100 > 5
  Message: "X% of values are missing across Y columns."

DUPLICATE RECORDS ALERT      [Severity: High]
  Trigger: Duplicate rows > 2% of total rows
  Formula: (Duplicate rows / Total rows) × 100 > 2
  Message: "X duplicate records detected."

BUDGET OUTLIER ALERT         [Severity: Medium]
  Trigger: Any numeric value > mean + 2 standard deviations
           OR any numeric value in top 5% of column distribution
           (whichever catches more records — use the broader threshold)
  Applies to: All numeric columns. Label uses column name.
  Message: "Budget outlier detected: [Project Name] is 2.3x above average."

CATEGORY DOMINANCE ALERT     [Severity: Medium]
  Trigger: Any single category accounts for > 40% of total records
           in a categorical column
  Applies to: All columns with fewer than 20 unique string values.
  Message: "[Category] represents X% of all records in [Column]."

DATA QUALITY ALERT           [Severity: Low]
  Trigger: Overall Quality Score < 75%
  Message: "Data quality score is X%. Review missing values and formatting."

NO ALERTS STATE
  Message: "No alerts detected. Your dataset looks healthy."

AI RESPONSE CONTRACTS
(Defines exact JSON structure returned by AI calls)
----------------------------------------------------------------

Executive Summary Contract
--------------------------
  interface ExecutiveSummary {
    overview:       string   // max 50 words
    topCategory:    string   // max 30 words
    risk:           string   // max 40 words
    recommendation: string   // max 40 words
  }

  Total summary word count must not exceed 200 words.
  AI prompt must instruct: "Return only valid JSON. No preamble."
  UI renders these four fields directly. Prompt changes that rename,
  remove, or reorder keys will break the UI and require a UI update.

Insight Confidence Contract
---------------------------
  interface InsightResult {
    insight:    string           // the insight text
    confidence: "High" | "Medium" | "Low"
    evidence:   string[]         // array of supporting data points
    metrics: {
      value:    number
      average:  number
      delta:    string           // e.g. "+34% above average"
    }
  }

AI Comparison Summary Contract
------------------------------
  interface ComparisonSummary {
    keyDifferences:    string   // max 40 words
    qualityAssessment: string   // max 30 words
    riskAnalysis:      string   // max 30 words
    recommendation:    string   // max 30 words
  }

  Total comparison summary word count must not exceed 150 words.

Rules Engine vs AI Switch Trigger
----------------------------------
  Stay rules-based when:
    Insights derived from aggregations, outliers, missing values,
    or basic correlations. Example: "Highest budget category."

  Switch to AI when:
    System must explain trends, generate recommendations,
    summarize multiple findings, or compare datasets narratively.

  Concrete threshold:
    Activate AI when Rules Engine covers < 70% of requested insights,
    OR user submits a natural-language query.
    Review this threshold at end of Sprint 2.

RISK REGISTER — Sprint 1A
--------------------------
Risk: Large CSV causes slow dashboard render
  Impact:     High
  Likelihood: Medium
  Mitigation: Always calculate KPIs, Alerts, Summary, and Reports
              from the FULL dataset regardless of size.
              Partial-row aggregation produces misleading insights —
              e.g. first 500 rows of a 100,000-row dataset may
              represent January only, hiding the real story.
              Paginate ONLY raw data tables and the data explorer view.
              Never paginate anything the user makes decisions from.

  Full-dataset processing targets:
              Under 10,000 rows:   process synchronously
              10,000–100,000 rows: process async with progress indicator
              Over 100,000 rows:   sample + stream with notice:
              "Analysing full dataset. This may take a few seconds."

Risk: Alert generation produces false positives
  Impact:     Medium
  Likelihood: Medium
  Mitigation: Use exact thresholds defined in Section 2.
              Add confidence note to each alert.
              Allow user to dismiss individual alerts.

Risk: Mobile layout breaks on smaller screens
  Impact:     Low
  Likelihood: Low
  Mitigation: Test on 375px viewport minimum before sprint close.

              a stale comparison silently.
              Hash-based keys invalidate automatically on any data change.

FEATURE 13: Activity Log (Personal History)
----------------------------------------------------------------

Decision Record
---------------
Option A (Audit Trail) considered and rejected.
DataPulse is not a compliance platform at this stage.
Audit trails require immutability and tamper-proofing at an
engineering cost not warranted for MVP.

Chosen: Option B — Personal History
Upgrade path: Audit Trail available as future enterprise feature.

Tracked Events
- Recent datasets viewed
- Recent reports generated
- Recent charts created
- Recent insights viewed

Behaviour
- User can clear entire history.
- User can remove individual entries.
- History persists across sessions (stored server-side per user).
- Maximum 50 entries. Oldest entry removed when limit reached.

Acceptance Criteria
- History updates in real time as user navigates.
- Clear all and remove single entry both functional.
- Accessible from sidebar or settings panel.

Success Metrics
- 30%+ of returning users interact with activity log.
  Measured via: Posthog — click on activity log items.
  Timeframe: 45 days post-launch.

Error States
- History empty:
  "No recent activity. Start by uploading a dataset."
